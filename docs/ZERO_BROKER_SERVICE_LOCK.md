# ZERO-BROKER SERVICE LOCK

## Completion criterion

A supported route is complete only when a real user can finish it without needing to ask a private broker, LPK, friend, senior worker, community chat, or unofficial intermediary what to do next.

A stage is **not complete** merely because the major process is documented.

A stage is complete only when the product covers:
- what to do,
- where to do it,
- what to prepare,
- what to pay,
- who receives payment,
- every known confusing field/choice,
- exact input/choice when officially determinable,
- examples for forms/documents that users must prepare,
- rejection-prone mistakes,
- completion condition,
- next action,
- official source,
- cycle/applicability,
- freshness/review status.

## Exact-answer rule

When the official source determines an answer:
> Give the exact answer first. Do not hedge.

When the official source does not determine an answer:
> Do not guess. Mark it as unresolved and block “safe to submit” status until verified.

## Broker-question test

For every stage ask:
> “If a broker were standing next to the user, what tiny questions would the user ask?”

Those questions become product requirements.

Examples:
- Which option do I select?
- Individual or company?
- Whose bank account?
- Which address?
- JPG or PDF?
- Original or copy?
- Which side of the paper?
- How many copies?
- Which color folder?
- Where do I sign?
- Do I write my current address or KTP address?
- Is this a fee or just required balance?
- Can I use my parent's account?
- Should I leave this blank?
- Can I use an old photo?
- Should spaces in my name match the passport?
- What date format goes here?
- What if the form wording is negative?

## Freshness rule

Mutable information must have:
- source URL,
- source/cycle,
- verified date,
- monitoring status,
- review status.

Official source monitors may detect changes automatically, but **must never auto-publish rule changes**. A changed source becomes review-required until a human-reviewed structured rule update is published.

## Product metric

Primary metric:
**Broker Question Coverage (BQC)**

BQC = verified broker-like micro-questions answered / broker-like micro-questions discovered

A stage cannot be called complete while any high-severity discovered question is unresolved.
