# KEP 경쟁 상용 앱 벤치마킹 기반 UI/UX 구조 전략 — 2026-10-31

## 목표
현 KEP의 장문 설명·카드 과밀·동급 우선순위 나열을 개선한다. 현재 상태, 다음 할 행동, 공식 출처, 필요 서류, 도움 요청을 중심으로 모바일 앱처럼 간결한 정보 구조를 만든다. **정보를 삭제하지 않고 계층화**한다. 정부/민간 서비스 구분 및 공식 출처/적용 회차/마지막 확인 시점 표시를 유지한다.

이미지·홍보 자료는 실제 최신 앱 UI와 다를 수 있으므로 구현 전 실제 앱을 사용해 최신 상태·하단 탭·홈·지원 절차를 검수한다. 디자인 원칙만 참고하며 카피·아이콘·레이아웃을 동일하게 복제하지 않는다.

## 포지셔닝
단순 EPS 시험 학습이나 외국인 취업 광고 서비스가 아니라, **E-9 준비생·근로자의 단계별 실행과 입국 후 필수문제 해결을 돕는 도구**.
- 사용자 상태별 두 구간: (A) 인도네시아 EPS 준비/선발/출국 전 (B) 한국 입국·근로 중.
- E-9 사업장 변경 및 취업 조건은 일반 구인구직 앱과 법적 조건이 다름. KEP는 정부 신청·채용 알선의 대체자가 아님.
- 정부의 무료 공개 정보 자체를 유료화하지 않음. 향후 유료 서비스는 반복 비용·시간 절약 등 실제 부가 효용 입증 후 결정.

## 화면 IA
### 공통 모바일 4탭
1. Beranda (홈): 현재 단계 한 개, 다음 행동 한 개, 공식 출처/경고, 계속 버튼.
2. Tahapan (내 단계): 전체 27개는 여기서만 펼침/검색 가능. 현재/완료/미확인 명확하게 구분. 이용자가 선택한 상태와 공식 인증된 상태 구분.
3. Alat (도구): Dokumen, Biaya, Kontrak/Gaji, Bantuan의 작업형 2x2 우선 메뉴. 해당 단계에 필요한 것 먼저, 나머지는 secondary.
4. Akun (내 정보): 저장·복원·설정·언어·개인정보·문의. 실구현 없는 로그인/백엔드 기능 약속 금지.
PC는 동일 IA를 반응형 도구 메뉴/사이드 내비게이션으로 노출.

### 홈 상단 고정 구성
- 비정부기관 표기 및 국가/직종/회차
- 현재 단계(사용자 선택)
- 다음 행동 제목(짧게), 1~2문장 설명과 단일 CTA
- 출처 상태: 검토됨/검토 필요/회차 미확인 (기존 모니터 상태와 정확히 연결)
- 중요한 공고·마감·사기경고는 안전상 반드시 노출
- 하단 2x2 작업형 메뉴
나머지 전체 설명은 `자세히`, 접힘 패널, 단계별 페이지로 이동.

### 단계 상세
1. 지금 해야 할 일 (짧은 문장)
2. 준비물 체크리스트
3. 공식 원문·기관·적용 회차·확인일
4. 다음 단계 / 돌아가기
5. 추가 설명 및 예외사항
출처 미검증 때 신청 가능/서류 완성/비용 확정처럼 단정하지 않는다.

### 한국 입국 후
- 급여 명세·근로계약 확인, 사업장 관련 문제, 생활 문의, 공공기관 상담 연결
- 단순 기사형 정보 대신 '지금 겪는 문제' 선택 → 필요한 자료 → 공식 상담 경로 → 기록 보관.
- 민감정보 노출/전송/저장 최소화. 실제 검증/제휴·전문가 자문 없이 법률 결과 보증 금지.

## 디자인 시스템
- 녹색/오프화이트/중립 회색, 의미 없는 화려한 색상·배지 남용 금지.
- 시각 계층: H1 → 현재 행동 → 보조 내용 → 출처/상세. 버튼/탭/상태 의미 일관성.
- 8px spacing, 최소 44px 터치 영역, 320px부터 가로 넘침 0, 200% 텍스트 확대, 대비 검사.
- 카드 밀도: 홈 메인 CTA 카드 하나, 도구 2x2, 경고 1개 중심; '카드 안의 카드' 최소화.
- 장문 공식 원문은 삭제하지 않고 세부 화면에 유지. 원어민 표현 검수 필요.
- 모든 모달 상단 X sticky, 하단 버튼 유지, 스크롤·Back·Escape·포커스 복귀.

## 실행 우선순위
P0: 기존 UX 변경·데이터 계약과 현재 Work PR 스택 비교. 제안과 이미 구현된 기능의 차이를 정확히 확인. 데이터 계약·공식 차단 상태 보존.
P1: 홈 IA, 현재 단계/행동 카드, 태그·하단 탭을 실제 코드로 리팩터링. **먼저 320·390px 시각 검사**, 27개 단계 회귀.
P2: 단계 상세와 도구 페이지의 정보 밀도를 줄이고 체크리스트/출처/예외를 분리. 입국 후 문제해결 진입점도 현재 기능 범위 내에서 정리.
P3: 한국어 개발 설명을 실제 사용자 인도네시아어로 다듬고 현지 사용자에게 과업 테스트 실시.
P4: 전체 Chromium/WebKit/Firefox 가능 범위 테스트, 실기기 검증, 사람 출처 승인, 동일 후보 staging, 디자인 승인 후 운영 배포.

## 완료 기준
- 첫 방문 후 30초 내 현재 단계 선택/다음 행동/공식 원문 이동을 스스로 발견하는지 실제 사용자에게 테스트.
- 주요 홈 행동이 첫 화면에서 보이고, 동일 단계에서 단일 명료한 CTA.
- UI에 공식 사실을 생성하거나 유효기간/비용/합격을 추측한 표현 없음.
- 기존 27단계, 문서팩, 백업·복원, 개인정보 구분, 출처 차단 계약 보존.
- 모바일 320/360/375/390/430/768/1280, 200% 확대, 모달 조작, keyboard/screenreader, 저장 오류 테스트.
- 소스 monitor review_required 등 모든 배포 차단 상태는 실제 근거·승인 전 해제 금지.
- 상용 앱 화면을 그대로 카피하거나 정부 로고/제휴를 암시하지 않는다.
