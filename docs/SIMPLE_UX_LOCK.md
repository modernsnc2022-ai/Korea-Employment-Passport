# SIMPLE UX LOCK

The product may be internally complex, but the user flow must remain simple.

## Default user experience

1. Show the user **one current action**.
2. If the user is unsure about anything, provide **one obvious question box**.
3. When the action is complete, the user presses **continue** and the app advances.

## Complexity rules

- Do not require users to understand internal terms such as BQC, source hashes, rule engines, or monitoring.
- Technical trust/freshness details belong behind a collapsed disclosure.
- Extra tools for a stage are collapsed by default.
- If a form has many fields, show **one field at a time** with exact instruction + example + what not to do.
- A date/call-specific rule must not appear as a universal rule.
- If the user's applicable announcement is unknown, say so plainly; do not make them understand the term "cohort".
- The primary button on a screen must correspond to the user's next real-world action.

## Usability test

A first-time user should be able to answer these without instructions:
- What do I do now?
- Where do I ask if I am confused?
- How do I move to the next step?

If any answer is unclear, the screen fails the usability lock.
